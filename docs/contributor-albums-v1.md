## 启动

需要 Node.js 24 或更新版本；复用项目现有依赖，没有新增 UI 库或数据库服务。

```sh
cd '/Users/xiaowenli/Projects/naoko-archive'
npm run dev
```

打开 http://127.0.0.1:3000/contributor 。普通模式可以保存、预览、提交审核；要在本机验收发布/退回/已发布记录的删除与恢复，停止普通服务后运行：

```sh
npm run dev:admin
```

这个命令启用明确标识的本机审核模式，不是真实用户登录。不要将开发服务器开放到公网。端口占用时添加 `-- --port 3001`，以终端打印的地址为准。

## 操作与数据

- `/contributor/albums` 可按名称、年份、厂牌和编号搜索；新建与编辑共用五分区表单。
- 草稿允许全部未填。提交至少需要标题、艺人；已有曲目须有名称，填写的日期、时长、网址须有效。日期支持年、年月、完整日期，不补造未知日月。
- 曲目可键盘上移/下移，支持 A1/B1 曲序、多人署名、保留空行的歌词。多份发行版本分别保存厂牌、编号、日期和真实购买链接。
- 保存成功后才显示保存反馈。新记录保存后获得稳定编辑地址；刷新与重启仍在。预览清楚标注草稿，不发布资料。
- 提交后进入待审核；本机审核模式下可批准或退回。已发布记录再次编辑时，公众仍看到上一份批准快照，直至重新批准。
- 删除须确认，保留历史并可恢复；并发编辑使用修订编号检查，冲突时拒绝覆盖。
- 默认本地编辑署名 `fly-me-to-1980`；全站发起人姓名保持现有设置。

默认实际位置：

```text
data/archive.sqlite       唱片、工作稿、已批准快照、修订、媒体索引
data/private-media/       实际上传图片，位于 public/ 之外
```

首次本地启动一次性导入现有六条唱片资料；保留原编号、厂牌、日期和曲目，旧版信息归入“待确认版本”，不推测载体。目录已加入 `.gitignore` 和生产构建追踪排除。可用 `ARCHIVE_DATA_DIR` 指定其他绝对路径。备份时先停止开发服务，再备份整个 data 目录（包括 SQLite 可能存在的 WAL/SHM 文件）；不要只复制数据库而漏掉私有图片。

## 媒体与公开范围

图片支持实际上传 PNG/JPEG/WebP（10 MB 以内），私有预览通过受保护接口读取；不会保存临时 blob 地址。音频本版仅登记元数据，未接音频上传、转码、云存储或下载。

歌词和图片默认 private。只有明确选择 licensed-public、确认具有发布权并经批准的版本才可公开；仅改变权限选项不会自动发布。音频元数据不产生公开文件地址。公开页面采用字段白名单，不传递草稿、编辑备注、存储键或未获许可的歌词。新唱片没有封面时使用文字布局，不生成虚构图片。

生产环境 `/contributor` 和私有 API 返回 404；生产公开页面仍使用原六条默认资料，不读取本地私人数据库。将来如要把本地编辑成果上线，需要先加入真正的服务端身份认证、贡献者/审核权限与会话、审计/存储部署，再明确启用发布链路；当前没有公网账户或公网审核功能。
