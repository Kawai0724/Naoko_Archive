# 删除整个专辑

## 页面入口

- 专辑管理/提交记录：每行“编辑”下方提供“删除整个专辑”。
- 专辑版本目录：版本列表下方提供同名入口，避免与单个“移除版本”混淆。
- 编辑专辑：原移除入口也统一使用同一组件和 DELETE API。

点击后确认框显示专辑名称、版本总数及恢复方式。请求期间禁用按钮；出现修订冲突或权限错误时直接提示，不假装删除成功。

## 接口

`DELETE /api/contributor/albums/{albumId}`

需要已获批账号的真实 HttpOnly 会话、同源请求和 JSON 正文：

```json
{"confirm":true,"expectedRevision":12}
```

成功返回 HTTP 200，结构与现有编辑接口一致：`{album, history}`。`album.deletedAt` 非空、修订号递增。失败状态：401 未登录；403 未获批、权限不足或跨站；404 无权访问/不存在；400 缺少有效修订号或明确确认；409 修订过期/已删除。旧 `PATCH action=delete` 兼容保留。

管理员可以删除任意专辑；普通成员只能删除自己的未发布、非待审资料。曾发布的专辑即使当前为草稿，也必须由管理员删除。页面按钮按同一服务端规则显示，API 不依赖按钮或客户端角色。

## 范围与恢复

沿用 `AlbumStore.transition(delete)` 的软删除：整张专辑及全部版本立即从公开目录、搜索及详情消失；公开媒体入口和共建媒体读取也拒绝已移除资料。保留全部版本、曲目、封面、COS/本机文件、权利状态、所有权、批准快照及修订历史，不执行 COS 删除，不修改存储桶权限。

专辑管理勾选“查看已移除”，点击“恢复”。沿用 `PATCH /api/contributor/albums/{id}`，正文 `{"action":"restore","confirm":true,"expectedRevision":13}`。已发布资料的恢复也必须由管理员操作；恢复保留之前批准的快照，不把未审草稿误发布。

## 验证

- 45 项测试通过，其中新增真实本机文件、多版本、多曲目专辑的删除/恢复回归，确认封面字节、批准快照、所有权及审核权限保留。
- `npm run typecheck`、`npm run build` 通过。
- 临时资料目录、本机 3417 端口、管理员测试密码 `album-delete-http-test-password` 启动生产测试服务后，运行 `node scripts/verify-album-deletion.mjs`。脚本仅调用固定的本机测试地址，绝不能对 SSH 转发生产端口执行。报告见 `docs/album-deletion-http-qa.json`。
- HTTP 测试覆盖完整 DELETE 路由的匿名、跨站、其他作者、待审、已发布、明确确认、修订冲突、全部版本 404、已移除列表、上传阻拦和原样恢复。
- 浏览器已核实专辑列表和版本目录入口，360px 两页均无横向溢出。截图为隔离测试环境 `docs/screenshots/whole-album-delete.jpg`。
- 部署只同步代码并保留独立资料目录，先备份现有数据库。生产验收只读取入口、核对方法支持和未经授权的请求拦截，绝不删除真实专辑。
