# 版本排序与审核

新建专辑默认按发行日期从早到晚排序。空日期、非法草稿日期排在末尾；相同日期保持稳定顺序，支持年、年月、年月日。服务端保存时执行排序，不依赖浏览器。

新增/编辑专辑、新增/编辑版本和专辑的版本管理页均有折叠入口“调整版本顺序”。上移、下移自动切换为手动排序，也可选择恢复按日期。新增专辑还没有版本时可先选择排序方式，随后新增版本继承此选择。

排序先保存为草稿，提交后进入现有内容审核。审核前公开目录和第一版本封面不变；批准后共同更新。管理员自己的调整也必须提交。审核消息包含提交人、可选原因、排序方式及前后顺序，版本用名称、编号、载体和日期辅助辨认。待审资料锁定，越权、旧修订和重复审核沿用现有服务端保护。

历史数据没有 editionOrder 时视为手动排序，以保留原来已经批准的次序；不批量改写数据库、历史、已发布快照或文件。可在工作台选择按日期并提交审核。

## 验证

- npm run typecheck、npm test、npm run build。
- tests/edition-order.test.ts：日期及未知值、稳定排序、编辑与新增版本、手动覆盖、历史兼容；作者及其他成员权限；提交、拒绝、重提、批准、首项封面变化与重启后持久化。
- 浏览器使用独立临时资料库，验证新增专辑/版本入口、手机排版、手动排序、保存刷新、申请理由、审核差异及批准后的公开次序；不对生产账号或专辑执行写入测试。
