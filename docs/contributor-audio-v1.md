# 添加封面与无损音源 · 2026-10-21

本次只更新本地 Contributor。基本信息去掉“原文标题”和“别名”输入框；历史数据与修订中的原值保留。分区改为基本信息、曲目、发行版本、添加封面、添加音源、来源与修订。封面、歌词纸、内页仍合计最多六张，音源不占图片名额。

## 使用

在 `http://127.0.0.1:3000/contributor/albums` 新增或编辑专辑，打开“添加音源”。

- **整张专辑**：选择一个整轨文件，归属于整张专辑。
- **按曲目上传 → 关联已添加的曲目**：仅列出当前版本已有的曲目，每次上传一个文件，不新增或重命名曲目。暂无曲目时先前往“曲目”添加；选定曲目前不能选择文件。服务端同样拒绝自动新建曲目。
- 曲目展开后可以“查看音源”，音源展开后可以“查看关联曲目”，双向切换并展开对应记录。可修改音源名称、发行版本、来源和曲目关联。
- 删除曲目会解除关联；原音源保留为“曲目待关联”，不错误标成整轨专辑。替换与移除保留历史文件，不销毁已批准快照的原文件。

## 文件与保存

支持 FLAC、PCM WAV、PCM AIFF、ALAC（.m4a），每个文件最多 4 GB。服务端使用 [music-metadata 12.2.3](https://github.com/Borewit/music-metadata) 读取实际编码、位深、采样率、声道和时长；AAC 编码的 M4A、伪造后缀和不可识别文件会拒绝。编码格式检查不判断录音母带来源。

当前表单先保存为草稿，再按文件逐个流式上传，界面显示进度。单个文件失败会清理其临时数据；曲目模式先选择已有曲目，文件名只用于音源名称。不会一次把整张专辑读入服务端内存。未进行实际 4 GB 文件的压力测试。

音源保存在 `data/private-media/<随机标识>.<格式>`，暂存位于 `data/private-media/.incoming/`，不在 `public/`。SQLite 的媒体索引与音频规格表保存真实规格，保存表单不能伪造已上传文件的编码或采样率。上传始终保存为私人音源；歌词、图片现有审批规则保留。公开详情、公开 API 和草稿预览均不提供私人音频文件或存储路径。生产环境仍关闭 Contributor 和私有 API；本次未部署公网。

## 验收

- 19 项测试通过，包括六图限制回归和四种音频格式、AAC 拒绝、流式清理、持久化、曲目关联、权限及历史快照。
- 实际 HTTP 验证：四种文件上传、拒绝自动新增曲目、关联已有曲目、私有 Range 分段读取、公开页面不泄露音源、替换和修订冲突，见 `contributor-audio-http-qa.json`。
- 浏览器检查桌面 1440×900、手机 390×844 与 360×800 的全部六分区，无页面横向溢出；双向曲目链接与关联已有曲目的文件选择模式通过，见 `contributor-audio-browser-qa.json`。
- Chrome 扩展仍未允许 file URL，自动文件选择被阻止；没有修改扩展权限。实际上传接口使用合成测试音频验收，文件选择后到上传完成的整段浏览器自动流程仍需手动检查。

运行仍使用 `npm run dev`，本机批准使用 `npm run dev:admin`。需要 Node.js 24+，新增的是音频解析依赖，没有引入 UI 库。测试合成文件位于 `tests/fixtures/lossless/`，不是商用录音。隔离 HTTP 验收命令：

```sh
ARCHIVE_DATA_DIR=/private/tmp/naoko-audio-editor-qa npm run dev:admin -- --port 3011
# 另一个终端，从同一项目目录运行：
python3 scripts/verify-audio-upload.py http://127.0.0.1:3011 --isolated-qa
```
